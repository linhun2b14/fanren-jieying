# 时点 / 触发 审计（机器产出，未改代码）

> 由 `node tools/audit-timing.js --md` 生成。人工逐条核对后的结论见 `docs/时点触发不符清单.md`。

审计分四层，逐层往下挖：

1. **①字段层** —— op 写进玩家状态的字段，全引擎有没有人读。
2. **①b 卡牌层** —— 这些死 op 分别被哪些卡用了。
3. **①c 常驻层** —— `passive: true` 的 op 不走 switch，而是由 `passives(pl)` 汇总；单独核查汇总出来的键有没有人取用。
4. **①d 生命周期层** —— 累加型字段（`x.F = (x.F||0)+n`）有没有在回合开始归零。

## ①c 常驻 op 通道（passives() 汇总后没人取用）

- `damage_shield` ⇒ （卡池里没人用）  
  ⓘ 卡池里没有任何卡用它，属预留 op
- `turn_no_combat_mana` ⇒ 【三目豹】(companion)  
  ⓘ 效果其实生效：L1290 写 self.noCombatMana，L973 回合结束读取；但该字段**从不重置**，每回合 +1 累积（三目豹越玩越强）
- `turn_no_combat_heal` ⇒ 【墨彩环】(companion)
