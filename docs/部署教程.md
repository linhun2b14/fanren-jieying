# 部署教程

从「本机试玩」到「公网给朋友玩」的完整步骤。全程只需要 **Node.js ≥ 18**，不需要 npm 安装任何依赖。

- 游戏服务：默认 **8094**（`server/index.js`）
- 卡片编辑器：默认 **8098**（`tools/editor/server.js`，**不要暴露到公网**）

> 本文里的 `fanren.example.com`、`192.168.0.10` 都是占位符，替换成你自己的域名 / 内网 IP。

---

## 0. 一分钟跑起来（本机）

```bash
git clone <仓库地址> fanren-jieying
cd fanren-jieying
node server/index.js
# → 访客请打开 http://127.0.0.1:8094
```

- 换端口：`PORT=8095 node server/index.js`；只绑本机：`HOST=127.0.0.1 node server/index.js`
  （Windows PowerShell：`$env:PORT=8095; node server/index.js`）
- 起完**先自检**（下面第 6 节），确认端口上跑的是新代码。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Node.js | **≥ 18**（开发环境 v24；用到 `crypto.randomUUID/randomBytes`、内置 `fetch`、`node --test` 无关） |
| 内存 / 磁盘 | 极低（纯内存房间状态，进程约 40～60 MB；仓库本身几 MB） |
| 依赖 | **零 npm 依赖**，`npm install` 不是必须的（`package.json` 只提供 `npm start` 之类的快捷脚本） |
| 浏览器 | 任意现代浏览器（需支持 SSE / EventSource：Chrome、Edge、Safari、Firefox 均可） |
| 系统 | Windows / Linux / macOS 都行；脚本 `run-fanren.cmd` 是 Windows 专用 |

## 2. 局域网联机（最常见：一群人在一个 WiFi 里用手机玩）

1. 在当"主机"的电脑上起服务（**绑 `0.0.0.0`**，默认就是）：

   ```bash
   HOST=0.0.0.0 PORT=8094 node server/index.js
   ```

2. 查这台电脑的局域网 IP：

   ```powershell
   # Windows
   ipconfig | findstr /i "IPv4"
   ```
   ```bash
   # Linux / macOS
   ip addr | grep "inet "        # 或： ifconfig | grep "inet "
   ```

3. 放行防火墙端口：

   ```powershell
   # Windows（管理员 PowerShell）——只对"专用网络"放行
   New-NetFirewallRule -DisplayName "fanren-jieying 8094" -Direction Inbound `
     -Protocol TCP -LocalPort 8094 -Action Allow -Profile Private
   ```
   ```bash
   # Ubuntu（有 ufw 时）
   sudo ufw allow from 192.168.0.0/24 to any port 8094 proto tcp
   ```

4. 其他人在浏览器访问 `http://192.168.0.10:8094`，输房间码加入。
   > 房间码是 4 位大写字母/数字，输入时会自动转大写。

**常见坑**：手机连的是"访客网络"/5G 热点，和主机不在同一网段 → 换个 WiFi；
或路由器开了「AP 隔离」，设备之间不能互访 → 关掉它。

## 3. 公网联机（外网也能玩）

推荐结构：**应用只监听 127.0.0.1（内网），由反代负责 HTTPS 与转发**。

```bash
HOST=127.0.0.1 PORT=8094 node server/index.js
```

### 3.1 Caddy（最省事，自动申请证书）

`/etc/caddy/Caddyfile`：

```
fanren.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8094
}
```

```bash
sudo systemctl reload caddy
```

Caddy 会自动向 Let's Encrypt 申请证书、自动续期，并且**默认不缓冲流式响应**，
所以 SSE 不用额外配置。

### 3.2 Nginx（手动配证书）

```nginx
server {
    listen 443 ssl http2;
    server_name fanren.example.com;

    ssl_certificate     /etc/letsencrypt/live/fanren.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/fanren.example.com/privkey.pem;

    location / {
        proxy_pass         http://127.0.0.1:8094;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;

        # ⭐ SSE（/api/stream）必须关缓冲，否则前端收不到实时推送
        proxy_buffering       off;
        proxy_cache           off;
        proxy_read_timeout    1h;     # 长连接别被 60s 掐断
        chunked_transfer_encoding on;
    }
}
```

> **SSE 反代三件套**：`proxy_buffering off`、足够大的 `proxy_read_timeout`、不要开 `gzip` 二次压缩
> （Nginx 自带的 gzip 会把流压住）。Caddy 这些默认都对。

### 3.3 端口/证书之外

- 路由器做端口映射（或云主机安全组放行 443）。
- **不要**把编辑器 8098 映射出去（它没有鉴权，能改卡池并写盘）。
- 房间码本身就是"口令"：4 位、房间内存态、房间没人了自动回收。想更稳就直接上 VPN（WireGuard/Tailscale），
  比裸奔公网舒服也更安全。
- 需要固定入口/统一门户，可以在前面再挂一层你自己的网关；本项目不依赖任何特定反代特性。

## 4. 常驻运行

### 4.1 Linux：systemd

`/etc/systemd/system/fanren.service`：

```ini
[Unit]
Description=Fanren Jieying (web board game)
After=network.target

[Service]
Type=simple
User=games
WorkingDirectory=/opt/fanren-jieying
Environment=PORT=8094
Environment=HOST=127.0.0.1
ExecStart=/usr/bin/node server/index.js
Restart=always
RestartSec=3
StandardOutput=append:/var/log/fanren.log
StandardError=append:/var/log/fanren.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now fanren
systemctl status fanren
```

### 4.2 Windows：计划任务 + 自愈脚本

仓库自带 `run-fanren.cmd`（纯 ASCII、自带"进程挂了 5 秒后重启"的循环）：

```powershell
# 注册成"开机即起、SYSTEM/当前用户均可"的计划任务
schtasks /Create /TN "FanrenGame" /SC ONSTART /RL HIGHEST /RU SYSTEM ^
  /TR "cmd /c <项目目录>\run-fanren.cmd" /F
schtasks /Run /TN "FanrenGame"
```

- 日志写在 `<项目目录>\logs\fanren.log`（脚本自己重定向）。
- 改端口/监听地址：编辑 `run-fanren.cmd` 顶部的 `PORT` / `HOST`。
- ⚠️ 计划任务里**不要**用 `timeout` 当 sleep（无控制台输入句柄会失败），脚本里已经改用 `ping -n`。

### 4.3 pm2（跨平台）

```bash
npm i -g pm2
PORT=8094 HOST=127.0.0.1 pm2 start server/index.js --name fanren --time
pm2 save && pm2 startup
```

### 4.4 Docker

仓库自带 `Dockerfile`（基于 `node:20-alpine`，零依赖，内置 `HEALTHCHECK`）：

```bash
docker build -t fanren-jieying .
docker run -d --name fanren -p 8094:8094 -e PORT=8094 -e HOST=0.0.0.0 \
  --restart unless-stopped fanren-jieying
# 想改卡池又不想重建镜像：把 data 挂进去
#   -v /srv/fanren/cards.json:/app/data/cards.json:ro
```

配合 compose：

```yaml
services:
  fanren:
    build: .
    ports: ["8094:8094"]
    environment: { PORT: "8094", HOST: "0.0.0.0" }
    restart: unless-stopped
```

> 反向代理容器要连它时，把 `ports` 换成 `expose` 并放进同一个 compose 网络即可。

## 5. 升级与数据

| 内容 | 存在哪 | 说明 |
|---|---|---|
| **卡池** | `data/cards.json`（磁盘） | 唯一的持久数据；改前先备份 |
| 房间 / 对局状态 | **进程内存** | 重启即清空（正在进行的房间会消失，属预期） |
| 备份文件 | `data/cards.json.bak-*` | 编辑器每次保存自动留 10 份 |
| 日志 | `logs/fanren.log` | 只有 `run-fanren.cmd` 会写 |

升级步骤（改的是 `server/` 或 `data/` 都必须重启进程，`public/` 下是静态文件、不用重启）：

```bash
git pull
# …若卡池有更新，先备份：cp data/cards.json data/cards.json.bak-$(date +%F)
sudo systemctl restart fanren            # 或： schtasks /End + /Run、pm2 restart fanren
node tools/deploy-check.js               # 确认端口上的进程确实换了新代码
```

**卡池备份/恢复**（编辑器里改崩了也在所不惜）：

```bash
cp data/cards.json data/cards.json.bak-manual      # 备份
cp data/cards.json.bak-editor-20261006-174310 data/cards.json   # 恢复某次自动备份
```

## 6. 部署自检（强烈建议每次部署后跑一遍）

```bash
curl -s http://127.0.0.1:8094/healthz                 # {"ok":true,...}
curl -s http://127.0.0.1:8094/api/version             # pid / 启动时间 / 引擎与卡池哈希 / stale
node tools/deploy-check.js                            # 一条命令比对"进程 vs 源码 mtime"
```

`/api/version` 里两个字段最有用：

- `engine.hash` / `cards.hash`：源码与卡池的内容指纹（改过就会变）。
- `stale: true`：**端口上坐着的还是旧进程**（常见于"以为重启了、其实端口被占、新进程静默退出"）。

完整回归（可选，改过代码再发版时跑）：

```bash
node tests/run-all.js --no-ui          # 引擎 + 服务端 36 套，不需要浏览器
node tools/verify-dsl.js && node tools/lint-cards.js
```

## 7. 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 别人打不开 `http://<IP>:8094` | 防火墙没放行 / 服务绑了 127.0.0.1 / 不在同一网段 / AP 隔离 | 见 §2 三条；`netstat -ano \| findstr 8094` 看监听地址是不是 `0.0.0.0` |
| 页面能开，但状态不实时更新、要手动刷新 | 反代把 SSE 缓冲了 | Nginx 加 `proxy_buffering off; proxy_read_timeout 1h;`（§3.2）；Caddy 默认没问题 |
| 重启后"改动没生效" | 端口上还是旧进程（起新进程时端口被占，静默失败） | `curl /api/version` 看 `started` 与 `stale`；`node tools/deploy-check.js`；先 kill 旧 pid 再起 |
| Windows 计划任务起不来 | 用了 `timeout` 当 sleep / 没带工作目录 | 用仓库自带 `run-fanren.cmd`（已用 `ping -n` 代替 `timeout`，且自己 `cd /d` 到项目目录） |
| 卡池改了但界面没变 | 浏览器缓存了静态文件，或**服务端**（`data/`）没重启 | 强刷 Ctrl+F5；`server/` 与 `data/` 改动必须重启进程 |
| 房间"自己没了" | 房间与对局都在内存里，进程重启即清空；房间空了也会回收 | 属预期；重开一局即可 |
| 编辑器 8098 无响应 | 编辑器进程被上一轮的旧实例占着端口 | 停掉旧进程再起；`curl http://127.0.0.1:8098/api/healthz` 看 `stale` |

## 8. 从零部署一遍（Ubuntu 22.04 + Caddy 示例）

```bash
# 1) 装 Node 20（nodesource）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs git

# 2) 拉代码
sudo mkdir -p /opt && cd /opt
sudo git clone <仓库地址> fanren-jieying

# 3) 先手工验一遍
cd /opt/fanren-jieying
PORT=8094 HOST=127.0.0.1 node server/index.js &
curl -s http://127.0.0.1:8094/healthz
kill %1

# 4) 交给 systemd 常驻（用 §4.1 的 unit 文件）
sudo useradd -r -s /usr/sbin/nologin games || true
sudo chown -R games:games /opt/fanren-jieying
sudo systemctl enable --now fanren

# 5) Caddy 反代 + 自动 HTTPS（用 §3.1 的 Caddyfile）
sudo apt install -y caddy && sudo systemctl reload caddy

# 6) 验证
curl -s https://fanren.example.com/healthz
node tools/deploy-check.js
```

至此，把 `https://fanren.example.com` 发给朋友就能开局了。
