### 3.2 受伤窗口前置（`server\engine.js` 的 `applyDamage`）

```
伤害进来 → 开【斗法】窗口（伤害还没落地，连减免都还没算）
        → 逆序收势：响应用 ctx.pending.value 改"待落地的伤害"
        → resume 回来落基础行动：减免 → 扣血 → "受伤时"自动效果（燕如嫣/慕沛灵）→ 濒死判定
```

- 四个受伤响应全部改成"改那笔待落地的伤害"：
  `damage_cancel`（→ 0）、`damage_multiply`（× N，基数＝待落地值）、
  `puppet_absorb`（→ 0，傀儡替伤：**血量根本不掉**，不再是"先扣再补"）、
  `damage_save_dice`（【遮天钟】掷骰抵消 / 6 点反弹**等额**，反弹额取待落地值）；
- `ctx.lostHp` 跟着 pending 走 → `$lostHp` 占位符、后结算的响应看到的都是已改过的数；
- `ctx.lethal` 是粗判（`生命值 − 待落地伤害 ≤ 0`）；`damage_multiply` 把人翻到致命时置真，
  后面才结算的【还阳术】（`if: {lethal:true}`）仍会被问出来；
- **零响应直通**不变：没人能响应时 `opening:false`，伤害立刻落地（不会平白多一次弹窗）；
- **删掉旧通道**：`ctx.deferredDeath` 整条退役（`resolvePending` 里那段事后判死删掉了）；
- 淘汰路径顺手补 `checkLastStanding`（与旧 deferred 通道一致，避免"最后一人被打死"要等下一次 `advance()`）；
- 前端文案：窗口期间「**即将**受到 N 点伤害」「这次伤害将使生命值归零——不出手就出局」，
  收势之后才有战报那条「受到 N 点伤害」（`publicState.pending.about` 新增 `pending` 标记）。

## 4. 顺手修的两个"咬人"的坑

1. **上一会话遗留的 8095 / 8097 进程在占端口**：新起的进程 `EADDRINUSE` 直接退出，端口上坐着的还是旧代码 ——
   全量回归打了 5 分钟才发现打的是旧服务。⇒ 线上加 **`GET /api/version`**（pid / 启动时间 /
   `engine.js` 与 `cards.json` 的 sha1 前 12 位 + mtime / **`stale`**：进程启动时的哈希 vs 现在磁盘的哈希）；
   编辑器 `/api/healthz` 也补了 `started` / `codeMtime` / `stale`（判据见 `docs\交接文档.md` §5.2）。
2. **编辑器的校验镜像会被 pid 复用继承**：镜像目录原来叫 `…-mirror-<pid>`，Windows 复用 pid 时
   `ensureMirror()` 会认下**上一个进程留下的旧镜像**（`.ready` 在就复用），于是旧 `effect-meta` 去校验新卡池 ——
   实测症状：编辑器一直报「【玄铁飞天盾】的 op `damage_cancel` 不在元数据表里」。
   ⇒ 目录名加上**启动时间戳**（`…-mirror-<pid>-<Date.now()>`），清扫逻辑改成按 `-` 前的 pid 探活。
