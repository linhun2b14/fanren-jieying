# 锁链（连锁）规则细则

> 依据用户裁定：**不加"每人限 1 张"的限制**，做成游戏王式锁链，**后进链的先结算**。
> 本文用大白话写规则，**不是代码**。代码改造在确认后另起。

---

## 一、一句话定义

**某个时点发生 → 谁满足条件谁就能打一张手牌进链 → 后来者先结算 → 结算完再看有没有人接着响应 → 没人响应就关链。**

---

## 二、链上的每一环记什么

每一环就是"某人打出的某张牌"，只记 5 件事：

| 字段 | 含义 | 例 |
|---|---|---|
| **是谁打的** | 玩家 | 张三 |
| **打的是哪张** | 牌 | 【寒冰珠】 |
| **响应的是哪个时点** | 事件 + 主体 + 阶段 | 事件`投骰`、主体`对方`、阶段`前` |
| **这一环的目标** | 如果有 | 指向李四 |
| **结算了没有** | 状态 | 未结算 / 已结算 / 已失效 |

⚠️ **"已失效"是必须的**：如果下面某一环把这一环的目标弄没了（比如目标被淘汰、牌被无效），
轮到他结算时要跳过而不是报错。这就是【虚天鼎】"使对方的牌无效"能生效的地方。

---

## 三、响应权限：谁能进链

**同时满足这三条才能进链：**

1. **时点对得上**：这张牌声明的时点 = 当前正在开的时点（事件、主体、阶段三个都要对）
2. **附加条件满足**：血够不够、境界够不够、有没有指定目标……
3. **付得起成本**：法力够、该弃的牌手上有

**另外：链已经关了就谁都不能再进。**

### 3.1 只问"真的有牌可响应"的人（2026-XX 修）

窗口的**成员资格**只由"这个人此刻有没有至少一张能打的牌"决定，顺序另说。具体：

- **一张能打的都没有 → 直接不排进队列**，不弹窗。
  （以前结果窗口按"赢家先、输家后"**无条件**把两边都排进去，于是手里干干净净的那一方
  也会被弹一次窗，点开只有"跳过"——用户报的"没有可以发动的牌也会询问"就是这个。）
- **付不起的人静默跳过**：需要 N 点法力却只有 M < N，不算"能打"，不排进队列、也不提示。
- **场上已经发动过的牌**不重复问（手牌不受此限 —— 手里还有牌就可以继续往上叠）。

### 3.2 场上（装备 / 同行者）什么时候进链

看卡文，不看花费：

| 形状 | 进不进链 | 例 |
|---|---|---|
| 卡文写明「**使用 / 发动**」的主动牌 | ✅ 进链（照问） | 【温天仁】"在对战中使用，消耗 3 点法力值"、【绿煌剑】【黑血刀】【青竹蜂云剑】（费用印在效果上，**在该效果自己的时点**问：获胜结算 / 我方投骰前…）、【墨彩环】"可消耗 3 点法力值恢复 1 点生命值" |
| 卡文写明「使用」但**不花法力** | ✅ 进链 | 【虚天鼎】"在对战中出牌阶段使用，**不消耗**法力值，使对方任意 1 张牌无效" —— 要选目标，必须问 |
| **触发型**的自动效果 | ❌ 不进链，到点自己生效 | 【慕沛灵】【燕如嫣】受伤回法力、【元瑶】濒危自救、【韩立】获胜夺装备、【离龟】放置抽牌、【银月】装备时抽牌 |

> 为什么触发型必须挡住：这些效果引擎已经用**专用通道**自动跑了（`hurtMana()`、`lowHpRescue()`、
> `runOnWinEffects()`…）。如果再摆出来问一遍，不只是多余 —— 玩家一点"响应"，
> 同一条效果会**跑第二遍**（回法力量翻倍）。
> 用户裁定：**不消耗法力的都是自动 / 被动**；需要付费的，只要时点和条件满足就得问。
> 数据上用 `auto: true / false` 可以显式覆盖上面的默认判断。

## 四、顺序规则（这是锁链的核心）

### 4.1 谁先有机会响应

**回合玩家优先** → 然后按座位顺序轮一圈。
（"回合玩家"= 现在轮到谁，不是"时点主体是谁"。）

### 4.2 结算顺序：倒序

链上的环按**进链时间**排成一条栈，**最后进来的最先结算**。

例：
```
时点：对方投骰前
 ① 张三 打【寒冰珠】（对方骰点 -2）
 ② 李四 打【颠倒五行阵】（强制重掷）
 ③ 张三 又打【黑血刀】（自己骰点 +2）
    → 没人再响应，关链
结算：③ → ② → ①
```

### 4.3 同一时点可以连出多张

没有限制。全往上叠，一起倒序结算。

### 4.4 每结算一环，都要重新问一遍"还有没有人响应"

不是"关链了才结算"。**每结算完一环，都重新开一次响应机会**——
因为某一环的结算可能正好满足了别人的条件。

```
结算 ③ 之后 → 重新问：还有人要响应吗？
   → 有：进链，成为新的最上面一环
   → 没有：继续结算 ②
```

---

## 五、链什么时候关

**两种情况：**

| 情况 | 说明 |
|---|---|
| **所有符合条件的人都表过态** | 每个人都可以"不响应"，所有人都表态完 → 关链 |
| **超时** | 兜底用。沿用现在胜负窗口的 **45 秒**；超时视为"不响应"，只跳过当前这个人，不关整条链 |

关链之后才开始倒序结算。

---

## 六、结算引发新时点怎么办（必须讲清楚）

**规则：一条链结算完，如果过程中产生了新时点，就为它开一条全新的链。**

举例：

```
链 A（时点：对方投骰前）
 ① 张三 打【寒冰珠】
 ② 李四 打【颠倒五行阵】
 → 关链 → 结算 ②（重掷）→ 结算 ①（-2）
 → 结算①的过程中，骰点变低导致对战结果变化……
 → 结算完全部后，进入"对战失败"时点 → 这是新时点 → 开链 B
```

**关键：不嵌套。** 链 A 必须整个结算完，才开链 B。
（不是"结算到一半插一条链进去"，那样会乱掉。）

### 6.1 「结算途中新开的时点」绝不能吞掉后面的窗口（2026-XX 修）

链 A 的某一环在结算时可能**当场触发一个新时点**——例如【风灵劲】结算时打出了伤害，
受伤那一格立刻要问一句（【遮天钟】【还阳术】）。

**新窗口一开，链 A 的"后半段流程"必须先挂起来，等新窗口关掉再接着跑。**

否则会出现这种极隐蔽的丢窗口：链 A 结算完 → 流程立刻往下冲 → 冲到"对战结果"那一格时，
发现**已经有一个窗口开着了**（就是刚开的那个受伤窗口）→ 按"不叠窗口"的规矩直接跳过 →
**赢家的【风云幡】【火弹术】从此再也没机会打**。用户报的"赢了却没人问我要不要用风云幡"
就是这条路径（当时【慕沛灵】的免费回法力还会白开一个受伤窗口，把结果窗口顶掉）。

实现上就是把 resume 挂到新窗口的 `ctx.resume` 上，串成一条恢复链。

## 七、谁不进链（这条是边界，必须守住）

| 谁 | 进不进链 | 理由 |
|---|---|---|
| **手牌打出的牌** | ✅ **进链** | 有成本（要付手牌/法力），能排序，链会自然收敛 |
| **场上的自动效果**（同行者、装备的常驻与回合触发） | ❌ **不进链**，当场直接生效 | 它们没有"被打出"这个动作，无从排序；每回合次数本来就有上限 |

**为什么不需要"每人限 1 张"**（原建议已撤回）：
触发是**基于"事件发生"**，不是**基于"状态满足"**——
受伤是一个已经走完的事件，回血不会回头再触发它；再加上每张响应牌都要付出去，
手牌有限，链必然收敛。

⚠️ **将来加卡时唯一要盯的形状：能互相触发的两张卡**（A 触发 B、B 又触发 A）。
当前卡池里不存在这种环。

## 八、和现在"胜负结算窗口"的关系

现在的胜负结算窗口是"每人限 1 张"，**这与锁链冲突**，改造时要统一成锁链：

| | 现在 | 锁链下 |
|---|---|---|
| 赢家/输家各限几张 | **1 张** | 不限，可连续叠 |
| 结算顺序 | 打完直接结算 | 进链，倒序 |
| 赢家的牌能不能被输家响应 | **不能** | **能**——这才是锁链的意义 |

例：赢家打【火弹术】（抽你 2 张宝物牌）→ 输家可以响应【踏云靴】（免罚）。
现在做不到，改造后可以。

## 九、要落到实现上，需要新增的三样东西

1. **一个"打开时点"的动作**：原来的流程点在走到该处时，不是直接往下走，而是先"开时点"。
   - 有人响应 → 建链
   - 没人响应 → 直接往下走（**零响应时行为要和现在完全一样**，否则会拖慢每一局）
2. **一个"链"的状态**：挂在当前对局里，记录上面 §2 那 5 个字段。
3. **一个"打断—询问"的通道**：让【遮天钟】【还阳术】这种"挨打那一刻才打"的牌有地方插。

**必须先做的三处打断**（其余时点先只做"能触发"）：
受伤 · 使用卡牌 · 被指定为目标。
这三处一上，**遮天钟、还阳术、阴魂丝、风灵劲、虚天鼎 这 5 张当场复活**。

---

## 十、一局的实际观感（避免做出"每步都卡"的体验）

零响应时零开销 —— 只有真的有人能响应，才会弹询问。
按现在的卡池，绝大多数时点都**没人能响应**，所以不会每步都停。

例如：抽牌那三个时点（灵气/宝物/法术同行者）按已定的规矩**只给抽牌的人自己**触发，
而目前没有任何卡挂在那三个时点上 → 永远是零响应 → 玩家感觉不到区别。
