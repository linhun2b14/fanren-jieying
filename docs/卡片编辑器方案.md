# 卡片编辑器 · 方案（待用户点头后开工）

> 目标：**图形化编辑卡牌** —— 时点、类型、费用、触发条件、效果（骰子相关 / 直伤 / 免伤…），
> 不用手改 JSON，也不用记 op 名字。

## 一、为什么这个项目做编辑器特别省事

底子已经齐了，编辑器几乎不用自己带词典：

| 现成的东西 | 编辑器怎么用 |
|---|---|
| `server/effect-meta.js` —— **效果元数据的唯一事实源**（`EVENTS` / `WHEN` / `OPS` / `CONDITIONS`，连中文标签与参数说明都有） | 全部下拉框 / 字段表单 **由它生成**，加新 op 时编辑器自动多一项 |
| `GET /api/meta`，前端已经拿它渲染卡牌详情 | 编辑器直接复用同一份，不会和引擎脱节 |
| `data/cards.json` 纯数据、无副作用 | 编辑 = 改这个文件，不用碰代码 |
| `tools/verify-dsl.js`（35 项）、`tools/lint-cards.js` | 编辑器自带"保存前先跑这两条"，写错当场拦住 |
| `data/cards.json.bak-*` 的既有习惯 | 每次保存自动备份 |

## 二、放哪、怎么跑（**不碰线上**）

编辑器放在**本机工具**里，不进游戏服务：

```
tools\editor\server.js       ← 一个独立的小 HTTP 服务（node 内置 http，零依赖）
tools\editor\index.html      ← 单页界面（原生 JS，和 public\app.js 一个风格）
启动：node tools\editor\server.js        → http://127.0.0.1:8098
```

- **只绑 127.0.0.1**，不对公网开。
- 它读写 `data/cards.json`（写之前先跑 `lint-cards` + `verify-dsl`，任一不过就拒绝保存）。
- 不参与 `run-all.js`（它是工具不是验收项）；但**改完卡池照样得跑全量回归**，界面上给个按钮提示。

## 三、界面（三块，一屏放下）

```
┌ 左：卡池列表 ────┬ 中：卡面编辑 ────────────┬ 右：实时预览 ─────┐
│ 🔍 搜索           │ 牌名 / 牌堆 / 类型       │ 就是玩家看到的     │
│ 宝物牌 (80)       │ 角标法力 / 适用境界      │ 那张卡（复用        │
│   · 青蛟旗        │ 张数 / 占位 / 装备位     │ public 的卡面样式） │
│   · 绿煌剑        │ ─── 效果列表 ───         │                  │
│ 法术牌 (33)       │ ［+ 加一条效果］         │ 点「按当前数据预览」│
│ 同行者 (78)       │  ① 时点 ▾（按 WHEN/EVENT）│ 会显示：           │
│ 灵气牌 (60)       │     条件 ▾ 参数…         │  · 什么时候能打    │
│                   │     效果 ▾ 参数…         │  · 高亮/置灰       │
│ ＋新建 / 删除      │  ② …                     │                  │
└───────────────────┴──────────────────────────┴──────────────────┘
```

**每条效果的编辑区由 `OPS[op].params` 驱动**：选了 `damage_target` 就只显示"伤害点数"；
选了 `combat_bonus` 就显示"加成值 + `if` 条件"。**不会再出现"手写 op 拼错"**。

**时点**用一个下拉，选项来自 `EVENTS`（总线）与 `WHEN`（旧写法）——
用户在界面上看到的是中文（"投骰 · 对方 · 前"），写进 JSON 的是坐标。

**触发条件**同样由 `CONDITIONS` 生成（`hp` / `realm` / `enemyRealm` / `companion` / `lethal` …），
比较符也是（`lte/lt/gte/gt/eq/higher/lower`）。

## 三·补 效果模拟沙盒（2026-10-05 加，用户点名要的）

> 用户原话："做一个卡牌效果模拟测试场景，可以挑选任意阶段、任意手牌、任意生命法力，
> 以及对手所要发动的手牌或者场上效果。"

界面在「校验 / 回归输出」下面加一栏 **效果模拟沙盒**，**默认收起**（用户 2026-10-05 追加要求：
"先设一个开关，不要常占着窗口下面"）—— 顶栏最右那个 **「效果模拟 ▸ / ▾」** 按钮就是开关，
收起时整块 `display:none`（不占地方）、展开状态记在 `localStorage`，下次打开还是上次那样；收起时连
`/api/simulate` 的元数据都不请求，展开才拉。

```
种子 / 当前回合 / 阶段(抽灵气·探索·抉择·行动·闭关) / 本回合已发起对战·已晋升 / 抽灵气不连锁
┌ 甲 ─────────────────────────┐ ┌ 乙 ─────────────────────────┐
│ 境界 生命 法力 灵气           │ │ 境界 生命 法力 灵气           │
│ 手牌 / 储物袋 / 法术区 / 同行者 / 傀儡位：选牌 ＋ → 牌片 ✕    │ │ …                            │
└─────────────────────────────┘ └──────────────────────────────┘
动作： 谁 ▾  做什么 ▾  哪张牌 ▾  打谁 ▾  牌堆 ▾   ［加入脚本］
脚本： 1. 甲 打出/装备【补气丹】✕   2. 乙 破招打出/发动【黑血刀】✕   …
输出： 每一步 ✓/✗ → 逐条战报 → 双方局面表 → 若窗口开着就列出候选牌按钮（一点就接上）
```

实现上的三个要点：

1. **用界面上那份卡池**（`POST /api/simulate` 的 `cards` 字段）：改完一张卡**不必先存盘**就能试效果 ——
   服务端走 `server/cards.js` 新增的 `setPool()` 注入（只影响**编辑器进程**，线上 8094 不受影响）；
   不带 `cards` 就回落到磁盘那份，行为可预期。
2. **无状态重放**：每次请求都从零建局 → 应用局面设置 → 依次执行动作脚本 → 回传
   `trace`（每步结果）+ `log`（引擎原始战报）+ `state`（局面快照，含对手手牌）。
   点候选牌 = 往脚本 append 一条再整体重跑，所以"下一步会怎样"随时可试、也随时可撤销（✕ 删掉那条）。
   同一个 `seed` 结果完全一致。
3. **动作白名单**：`play / respond_play / respond_pass / promote / combat / roll / draw_* /
   choose_draw / seclusion / discard / dismiss / activate / end_turn` —— 就是引擎 `act()` 认的那套；
   卡牌用**牌名**引用（uid 由服务端按固定规则分配，hand 优先），牌名写错会明确报错。

自测：`selftest.js` §5.6（端点 / 战报 / 对手响应 / 注入卡池 vs 磁盘 / 不写盘）、
`selftest-browser.js` ⑦（真浏览器里摆牌 → 加动作 → 运行 → 战报与局面表）。

## 三·补2 效果**蓝图视图**（2026-10-05 加，用户："效果列表这边不够傻瓜直观，应该是那种蓝图式的"）

卡面编辑的「效果」区现在是**双视图**，右上角一键切换（选择记在 localStorage，默认蓝图）：

| 视图 | 干什么 |
|---|---|
| **蓝图视图**（默认） | 按**时机**把效果分块，每块画成「时机 → 条件 → 效果」一条竖线：块头写明时机名字 + 引擎坐标 + **应对状态**（卡级/效果级/不带）+ 可用次数；块内每条效果 = 一个 ↓ 箭头 + 该效果的编辑卡（时点、条件、op、参数都在里面，改的还是同一份 JSON） |
| 表单视图 | 老的平铺列表：一条条 eff-card（复杂卡、冷门字段、原始 JSON 用这个） |

三轴模型在这一屏同时呈现：**轴 1 时机**（块头）、**轴 2 条件**（支线里的条件行）、**轴 3 效果**（支线里的 op + 参数）。

**op 下拉按 13 个「大类」分组**（`effect-meta.js` 的 `OP_GROUPS`，编辑器与两个视图共用）：
回合 / 手牌 / 生命 / 防御 / 法力 / 灵气 / 晋升 / 抽取 / 骰子 / 战力 / 封锁与无效 / 夺取·弃置对方的牌 / 装备与场上。
用户给的 11 类之外，我补了「晋升」「装备与场上」两类 —— 否则减晋升消耗、启用费、获得法术牌这些效果没地方放
（它们的**条件侧**仍在轴 2：场上有X / 已装备X / 晋升时…）。没登记的 op 会落到「未分类」组里，加了新 op 记得补一行。

**🎲 掷骰分支编辑器**（`roll_branch` 专用，就是用户说的"是否要投骰子：值可多选，值后面都可接后面的效果"）：
每条支线一排 1~6 点数按钮（点一下归到这条支线，可多选）+ 支线自己的子效果列表（二级 op 下拉 + 参数，允许
`$face` / `$lostHp` 占位符），另有「兜底」行收没勾中的点数。子效果不写时点（跟着这次掷骰走）。

自测：`selftest-browser.js` ⑧（时机块 / 应对徽章 / 三条支线的点数勾选 / 点「3」归类 / 标脏 / 双视图切换）+
截图存档 `ref\shots\editor-blueprint.png`。

## 四、校验与安全（这是重点）

1. **保存三步走**：`lint-cards` → `verify-dsl` → 数量校验（80/33/78/60）。
   任一步不过就**不写盘**，把错误原样显示在界面上。
2. **写盘前自动备份** `data/cards.json.bak-editor-<时间戳>`（最多留 10 份，旧的自动删）。
3. **"这一条效果引擎认不认"**：编辑器直接读引擎源码里的 op 清单（`effect-meta.js` 的 `OPS`），
   凡是 `OPS` 里没有的 op 一律红色标出 —— 正好治"只写不读的幽灵效果"这个老毛病。
4. **改完提醒跑回归**：界面上一个按钮 `node tests\run-all.js --no-ui`（只跑引擎侧，几十秒），
   结果直接显示。**不自动重启线上服务**（那是另一回事，要走运维流程）。

## 五、分期（建议）

| 期 | 内容 | 估算 |
|---|---|---|
| **一期** | 只读浏览 + 全字段编辑 + 校验保存 + 备份。能改"时点/类型/费用/条件/效果/张数/占位"。 | 主体工作量在这 |
| **二期** | 新建/删除卡、复制卡、批量改张数、diff 视图（改前/改后对照） | 小 |
| **三期** | 平衡试跑：一键跑 `balance-stats.js` 并把"改前/改后"两组数字并排显示（它已经是**确定性**的了，能直接对比） | 小但很有价值 |
| **四期** | 从卡面照片辅助填表（`ref/su-cai/` 的抄录已经在手，可以做成"照抄录预填"） | 可选 |

## 六、明确不做的

- **不做在线编辑**（游戏服务不暴露写接口，公网上谁都能改卡池太危险）。
- **不做"改完立即生效到线上"** —— 编辑的是磁盘上的 `cards.json`，要不要部署是运维决定。
- **不另起一套效果词典** —— 一律读 `effect-api/meta`，避免又出现"两处各写一份、改一处忘一处"。
