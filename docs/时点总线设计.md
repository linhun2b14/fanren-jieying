# 结婴之战 · 时点总线设计（对照表）

> 目的：把"时点"从现在的 **18 个零散 `when`**，改成按**回合流程**走的一条**总线**，
> 并且每个时点都严格带**我方/对方**两个主体。
> 本文只做设计，**未改动任何代码**。
>
> 已定下的两条前提（用户确认）：
> 1. **抽牌类时点只给"抽牌的人自己"触发**，对手不能插。
> 2. **时点严格分我方/对方**——因为【阴魂丝】这类牌的时点本身就长在对方身上。
>
> 图上的两处修订（用户已同意）：
> - 补一个节点 **「对战宣告 / 被指定为目标」**（【阴魂丝】【风灵劲】靠它）。
> - **「晋升前」留作占位**，现在没有任何卡需要，不为它做机制。

### 第 3 步实际怎么做的（比原计划省一半）

原计划写的是"要动所有卡的 `when`"。真做的时候改成更省的做法：**卡牌数据一个字都不用改**。

- `server/effect-meta.js` 新增 **`EVENTS`**（19 个事件，权威表）和 **`WHEN_TIMING`**（把现有 18 个 `when` 映射到总线坐标）。
  - 事件声明 `label` / `subject`（`'both'` = 分我方对方；`'none'` = 各自视角）/ `phases` / `selfOnly`（抽牌类不给对手插）/ `interrupt`（可打断的独立事件）。
  - `timingOfWhen()` / `timingOfEffect()` / `timingLabel()` / `eventLabel()` 对外统一出口；前端经 `/api/meta` 拿到 `events` 与 `whenTiming`。
- `server/engine.js` 新增 **`fireTiming(state, event, phase, ctx)`** —— 时点总线本体，**零响应直通**：
  - 没人能响应 → 立刻返回 `{opened:false}`，**状态一个字节都不动**（这是"行为与旧版完全一致"的保证，有测试盯着）；
  - 有人能响应 → 如实记进 `state.timingLog` + 战报留一行，**但不打断流程**（询问层留给第 4 步）。
  - 每次调用只给 `state.timingFired` 记一个计数（证明流程点真被走到了，成本可忽略）。
- **新补的 7 个挂点**（此前连位置都没有）：法力恢复、抽灵气、抽宝物、抽法术/同行者、晋升前、卡牌使用前/后、对战宣告（攻守各一次）、战斗选择目标、回合结束、闭关。

**主体语义（易错点，已写成注释+测试）**：
事件的"主体"= 这事发生在谁身上；**能响应的是卡主**。
卡的 `when` 是「我方…」→ 主体本人响应；是「对方…」→ **对家**响应。
例：【寒冰珠】「对方投骰**前**使用」——主体是那个**要投骰的人**，拿牌响应的是他的**对家**。

**结果**：总线里的 19 个事件全部就位且有流程点会走到；因为现在**没有任何卡挂在"新补的时点"上**，
所以实际运行时这些时点永远零响应 —— 这就是第 3 步"行为与旧版完全一致"的含义。
回归测试 `tests/timing-bus-test.js`（67 项）盯着元数据完整性、零响应不动状态、主体对称、passive/activate 不当时点。

### 第 4 步：打断层（三处询问点）

**核心**：`state.pending` 一个打断窗口 + `ctx.resume` 恢复闭包。
有人能响应就挂起流程，等人表态；没人响应就 `opened:false` 照旧往下走。

- **三处打断点**：`applyDamage`（受伤）、`doPlay` 出牌前（使用卡牌）、`doCombat` 建好对战后（被指定为目标）。
- **锁链**：后进链的先结算；出过牌的人能继续叠；队列里没人有牌了就自动结算。
- **淘汰延后**：致命伤害不立刻判死，窗口关掉后再决定 —— 【还阳术】才救得回来。
- **受伤窗口是"事后补救"**：伤害先落地，响应牌把刚扣的血补回来 / 反弹等额。
  这样不必把 `applyDamage` 的所有调用方改造成可暂停的，代价几乎为零、对玩家等价。

| 卡 | 新时点 | 效果 |
|---|---|---|
| 【阴魂丝】 | `combatDeclare·foe` | 我被指定为目标时，当场封锁对方本场的消耗类宝物牌 |
| 【风灵劲】 | `combatDeclare·foe` | 任意回合、有人发起对战时，让发起者受 1 点 |
| 【虚天鼎 乾蓝冰焰】 | `useCard·before·foe` | 对方出牌那一刻，**把那张牌直接无效掉** |
| 【遮天钟】 | `hurt·self` | 挨打时掷骰抵消 / 反弹（同时保留"任意回合预防性使用"） |
| 【还阳术】 | `hurt·self` + `if.lethal` | 只在**致命**伤害时出现，把人从 0 血拉回 2 点 |

回归测试 `tests/interrupt-test.js`（63 项）。

**v1 已知限制**：多目标伤害只会开第一个受伤窗口（`state.pending` 已存在时跳过后续）；留到第 6 步。

### 第 5 步：`combatStart` 瘦身（19 张 → 10 张）

`combatStart` 原本是个杂物抽屉，19 张牌全塞在这儿。现在按五类分流：

| 类 | 张数 | 结果 |
|---|---|---|
| ① 纯常驻战力修正 | 6（啼魂、寒蛟、六翼霜蜣、紫灵、王蝉、蛮胡子） | ✅ 改标 **`standing`（常驻·对战修正）**，不再占时点 |
| ② 有动作词、该可选发动 | 3（温天仁、凌玉灵、银月） | 🟡 **仍留在 `combatStart`**，待定（见下） |
| ③ 真·对战出牌阶段 | 6（金光砖符、天雷子、朱雀环、青火雷、敛气术、青元剑诀） | ✅ 本来就对，保持 |
| ④ 被 hack 的 | 3（阴魂丝、风灵劲、虚天鼎） | ✅ 第 4 步已搬去新时点 |
| ⑤ 纯噪音 | 1（绿煌剑的 `combat_bonus:0`） | ✅ 已删 |

**做法**：
- `effect-meta` 新增 `standing`（`kind:'passive'`，映射到 `event:null`，**不是出牌窗口**），
  并新增 `COMBAT_BONUS_WHENS = COMBAT_WINDOWS + ['standing']`。
- `companionCombat()` / `activateCombatCompanions()` 改成用 `COMBAT_BONUS_WHENS` 收集 —— 常驻加成照样算得出来。
- **顺带修掉一个真 bug**：`activateCombatEquips()` 原来只按 `isCombatEffect(op)` 判"这件装备是不是对战相关"，
  于是【绿煌剑】（效果是"获胜时对方额外受 1 点伤害"，op 是 `damage`）被当成"没有对战效果"，
  **从不收低境界装备的对战启用费**。原来那条 `combat_bonus: 0` 恰恰是它唯一被认出来的理由 ——
  所以删掉"噪音"时才发现：**它不是噪音，是启用费的触发点**。
  现在改成**按效果落在哪个时点**判对战相关（对战窗口/常驻修正都算），绿煌剑的费用照收，且不再需要那条 `+0`。

**② 这 3 张为什么留着**（要你拍板）：
它们的卡文都带动作词 —— 温天仁「在对战中**使用**，消耗 3 点法力值」、凌玉灵「对战中投骰**前使用**」、
银月「对战时可额外投 1 次骰子」—— 意思是**玩家自己决定要不要发动**。
但现在它们是**无条件自动生效/自动扣费**的。要改成可选，得给对战的 `pre` 阶段和投骰前各开一个询问窗口
（打断层的机器已经有了）。**待定，因为这会改变对局节奏**（每次开打/每次投骰都会问一句）。

#### 5.1 ②已定：判据 =「消耗法力才能发动 → 主动询问，不消耗法力 → 自动」

用户裁定后落实：

| 卡 | 卡文 | 判据 | 结果 |
|---|---|---|---|
| 【温天仁】 | 在对战中**使用**，消耗 **3 点法力值** | 消耗法力 | ✅ 改**主动询问**（新事件 `combatOpt`） |
| 【墨彩环】 | **可消耗 3 点法力值**恢复 1 点生命值 | 消耗法力 | ✅ 顺带改**主动询问**（`turnEnd` 时点） |
| 【凌玉灵】 | 对战中投骰前使用，骰点 +1 | 不消耗 | ✅ 保持**自动** |
| 【银月】 | 对战**可**额外投 1 次骰子 | 不消耗 | ✅ 保持**自动** |

- 新增事件 **`combatOpt`（对战·可选发动）**，与 `combatPlay` **必须分开** ——
  后者是"对战出牌阶段"这个正常出牌窗口，`when:'combatStart'` 的 6 张手牌挂在那里；
  若把 `combatPlay` 设成打断事件，所有那些手牌都会变成"可选发动"的候选，每次开打都被强制问一遍。
- **发动费只扣一次**：`respondPlay` 只检查付得起吗，扣费挪到 `resolvePending` 统一做。
- **付不起就不开窗**（`timingResponders` 跳过付不起的候选），避免弹出只能点"放弃"的空窗口。

**按同一判据还需拍板的**：**低境界装备的对战启用费**（绿煌剑 3 / 黑血刀 2 / 青竹蜂云剑 1 / 青元剑诀 2）
也是"消耗法力才能发动"，通则该改主动，但会带来"每次开打问一句"的节奏变化 —— 待定。

#### 5.2 通则定稿：「需要付费的都要询问；付不起自动跳过」

用户拍板：**每次开打都要问，要改**。核心通则：
> **只要需要支付费用，且时点与条件都满足，就得询问；付不起则自动跳过询问（不开空窗口）。**

据此把 **4 张低境界装备的对战启用费** 也改成主动：

| 卡 | 启用费 |
|---|---|
| 【绿煌剑】 | 3 |
| 【黑血刀】 | 2 |
| 【青竹蜂云剑】 | 1 |
| 【青元剑诀】 | 2 |

- 新增 op **`enable_equip_combat`（支付对战启用费，本场启用此装备）**，写成
  `{event:'combatOpt', subject:'self', op:'enable_equip_combat', manaCost: <角标法力>}`。
- `combatOpt` 窗口改成 **`allSides`**：攻守**双方**都要被问（每个人只被问到自己的牌）。
- **`combat` 新增 `equipEnabled: {玩家id: {装备uid: true}}`**：
  只有付过费的装备，本场才提供加成。没付 → 本场它的**所有**对战效果都不生效
  （`activateCombatEquips` 按它过滤，`collectEffects` 也按它过滤，所以【绿煌剑】的"获胜时+1伤害"同样被挡住）。
  ⚠️ `enable_equip_combat` 自己必须豁免这个门 —— 它是"付费"那个动作，被门挡住就永远开不出窗口（踩过）。
- **不再自动扣费**：`activateCombatEquips` 只统计已启用的，`paid` 恒为 0 的路径由玩家主动付费取代。
- 高境界装备（装备时已付过）与 0 费装备一律免费、无需询问。
- 回归：`tests/equip-combat-test.js`（17 项）、`tests/interrupt-test.js` 第 [J] 节（86 项）——
  含一条**全池体检**："所有低境界 + 有角标法力 + 有对战效果的装备，都必须有付费询问"，防止以后加卡漏掉。

## 一、模型：三个词

每个时点 = **事件** + **主体** + **阶段**

| 词 | 取值 | 例 |
|---|---|---|
| 事件 | 回合开始 / 法力恢复 / 抽牌 / 晋升 / 使用卡牌 / 对战宣告 / 选择目标 / 投骰 / 胜负 / 回合结束 | 「投骰」 |
| 主体 | **我方** / **对方** | 主体 = 对方 |
| 阶段 | 前 / 后（有些事件没有阶段） | 前 |

读法：
- **「对方投骰前」** = 事件`投骰`、主体`对方`、阶段`前` → 我作为旁观者响应
- **「我方投骰前」** = 事件`投骰`、主体`我方`、阶段`前`
- **「被指定为对战目标」** = 事件`对战宣告`、主体`我方`（我是受害者）

关键：**同一件事，从不同主体看是两格。** 现在引擎只有"投骰"这一件事做到了，
其他事件全被盖成了单一视角。

## 三、盘出来最大的一个问题：`combatStart` 是杂物抽屉

实测 **19 张牌**挂在 `combatStart` 上，但它们其实是三类完全不同的东西：

| 类 | 有几张 | 卡 | 它们真正是什么 |
|---|---|---|---|
| **① 常驻战力修正**（被硬塞进战斗时点） | **6 张** | 啼魂、寒蛟、六翼霜蚣、紫灵、王蝉、蛮胡子 | 见下节。**不需要时点** |
| **② 其实是主动技能 / 有真时点** | **3 张** | 温天仁、凌玉灵、银月 | 卡文里有"使用 / 可"这些**动作词**，是真时点或可选动作 |
| **③ 真·出牌阶段** | 6 张 | 金光砖符、天雷子、朱雀环、青火雷、敛气术、青元剑诀 | 卡文写"对战出牌阶段使用"的**手牌**，这才是真的时点 |
| **④ 被 hack 的** | 3 张 | **阴魂丝**、**风灵劲**、**虚天鼎** | 真正的时点图上还没建，只能先挂这儿 |
| **⑤ 纯噪音** | 1 张 | **绿煌剑**（对战修正是 `+0`，卡文只讲获胜时+1伤害） | 直接删掉这条 |

**总计 6+3+6+3+1 = 19** ✅

### 怎么一眼分辨"常驻加成"和"真时点"？**看卡文有没有动作词。**

| 卡文写法 | 性质 | 例子 |
|---|---|---|
| 「**对战时**，【战力值】+1」 | **常驻加成**——没有动作，是一盏一直亮着的灯 | 啼魂、寒蛟、六翼霜蚣、紫灵、王蝉、蛮胡子 |
| 「对方投骰**前使用**」 | **真时点**——有"使用"这个动作，是一个可以响应的瞬间 | 寒冰珠 |
| 「当你**受到**伤害**时**」 | **真时点** | 慕沛灵、燕如嫣 |

**第①类 6 张的完整卡文**（全部都是"对战时+X"，没有任何动作词）：

| 卡 | 卡文原句 | 条件 |
|---|---|---|
| 啼魂 | 对战时，【战力值】+1 | 无条件 |
| 蛮胡子 | 若生命值≥4点，对战时战力+1；若≤3点，对战时战力+1 | 反正一定有 1 张适用 |
| 寒蛟 | 若和【离龟】一起放置，在对战时，【战力值】+1 | 同场有离龟 |
| 六翼霜蚣 | 若生命值≤3点，在对战时，【战力值】+1 | 残血时 |
| 紫灵 | 在对战中，对方的境界高于你，你的战力+1 | 越级时 |
| 王蝉 | 对战境界高于你的修士时，战力+1 | 越级时 |

**建议**：这 6 张搬去"常驻数值"（和 `passives()` 汇总走同一条路），不再占时点。
好处是 `combatStart` 从 19 张瘦到 10 张，且加新卡时不会再有人把常驻加成塞进战斗窗口。
坏处是要重新验一遍这 6 张的战力数值。

**第②类 3 张要单独处理：**

| 卡 | 卡文 | 该怎么归 |
|---|---|---|
| 温天仁 | 「在对战中**使用**，消耗3点法力值，使对方战力-1」 | 是**可选动作**（现在是无条件自动扣 3 点法力，玩家不能拒绝）→ 归"主动技能"或"对战出牌阶段可选" |
| 凌玉灵 | 「对战中**投骰前使用**，骰点+1」 | 真时点 = **投骰前**，不是常驻 |
| 银月 | 「当储物袋中有装备，对战时**可**额外投1次骰子」 | 有"可"→ 可选动作；且带"每回合 1 次"限制 |

### 第 6 步：结果窗口改成锁链（已完成）

原来的结果窗口是**定制机制**：`resultStep`（win→lose）+ `resultUsed`（每方限 1 张）+ `advanceResultWindow()` 推进，
两边各出完一张就直接结算。现在换成**时点总线上的锁链**：

- `combatResult` 设成 `interrupt: true`，结果窗口只开**一个**询问，不再是"两步走"。
- **阶段按卡主角色判**（`ctx.resultRole`）：赢家只能打「获胜时」、输家只能打「失败时」；
  所以同一个窗口里两边的牌都能进 —— 这就是锁链的基础（原来必须分两步，输家没机会响应赢家打出的牌）。
- 排队顺序显式给 `ctx.order = [赢家, 输家]`（赢家先表态）；出过牌的人留在队首，还能继续叠。
- **倒序结算**由 `resolvePending` 保证；结算完才 `resume()` → `settleCombat`。
- `handOnly: true` —— 场上的 win/lose 效果（【绿煌剑】【风雷翅】）**不进链**，它们仍是自动触发
  （由 `runOnWinEffects` / `settleCombat` 负责），不能被摆出来问。
- 删掉：`canActInResult` / `advanceResultWindow` / `markResultPlay` / `resultStep` / `resultUsed`；
  `doPlay` 在结果阶段直接拒（要出牌就走 `respond_play`）；`result_pass` 保留为 `respond_pass` 的别名（兼容旧前端）；
  `armWatchdog` 的结果分支删掉（挂起时由 pending 的 60 秒超时兜底）。
- 前端：结果窗口只画状态条，出牌/跳过统一走「时点询问」弹窗。

回归：`tests/interrupt-test.js` 第 [K][L] 节 —— 赢家先出、输家可响应、**倒序结算**
（用战报里两行「锁链结算：…」验证顺序）、没人有牌时不开窗直接结算。

**还没铺到的**：投骰窗口（`roll` 的 before/after）与平局窗口（`tie`）仍走各自的老机制。

## 六、还要你拍板的两件事

**1. ✅ 已定：不加限制，做"锁链（连锁）"。**
规则：某时点发生 → 满足条件的人就能打出手牌进链 → **后进链的先结算**（倒序）
→ 每结算一环再看有没有人继续响应 → 没人响应则链关闭 → 若结算又引发新时点，就**为它开新链**。

> **为什么不需要"每人限 1 张"**（原建议已撤回）：触发是**基于"事件发生"**，
> 不是**基于"状态满足"**。受伤是"已经发生完的一个事件"，回血不会再回头重新触发它；
> 再加上每次响应都要**付出一张手牌**，链必然收敛。
> 当前卡池里**不存在"互相触发的环"**（A 触发 B、B 又触发 A），所以无需闸门。
> ⚠️ 将来加卡时唯一要盯的形状：**能互相触发的两张卡**。
>
> 进链边界：**只有"打出手牌"才算响应进链**（有成本、可排序）；
> 场上的自动效果（同行者/装备的常驻、回合触发）不排队，当场直接生效。

其他 3 个细节（用户已确认）：**回合玩家优先响应** → 同一时点可连出多张、全往上叠 →
所有人表过态就关链，另配**超时兜底**（沿用现在胜负窗口的 45 秒）。

**2. ✅ 已定：常驻战力修正搬出 `combatStart`（实为 6 张，不是 10 张）。**
