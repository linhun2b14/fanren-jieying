### 2.1 先攻 / 后攻：**只在运行时存在**

阶段图上的「先攻出牌阶段 / 后攻出牌阶段」在**数据里是同一格** `roll · 前`（先攻／后攻由引擎在运行时判定）：

- **卡面 / 编辑器**（静态数据）：用中性名 —— 「对战阶段 · 我方投骰前」「对战阶段 · 对方投骰前」；
- **斗法弹窗 / 战报**（运行时）：`META.timingLabelIn(t, {attacker})` → 「先攻出牌阶段 / 后攻出牌阶段」、
  「先攻投掷骰子阶段 / 后攻投掷骰子阶段」（只有引擎知道投骰的这个人是不是先攻）。

→ **写不出"只在先攻时 / 只在后攻时"的牌**：数据里没有这个概念。这是设计如此 ——
【青火雷】这类"我投骰前"的牌，先攻后攻都该能用。

### 2.3 时点 ≠ 条件：**套装 / 联动**走 `if`（不在上面这张表里）

用户问过"独立里面有套装判定吗？有些牌和另一张牌一起打出有加成、同行者某两个同场有额外加成"：

**套装不是时点，是条件** —— 时点管"什么时候能触发"，套装管"满足什么才生效"，所以它在 `if` 里：

| 写法 | 含义 | 现有实例 |
|---|---|---|
| `if: { companion: '离龟' }` | 场上有这张同行者 | 【寒蛟】"与【离龟】同场战力+1" |
| `if: { companion: ['离龟','铁火蚁'] }` | **这些全在场**（套装） | 待用 |
| `if: { companionAny: ['离龟','南宫婉'] }` | 其中任一位在场 | 待用 |
| `if: { onField: ['绿煌剑','青元剑诀'] }` | 自己**场上**（储物袋＋法术区＋同行者＋傀儡）这些牌全在 | 待用 |
| `if: { onFieldAny: [...] }` | 场上任意一张 | 待用 |
| `if: { playedThisTurn: '补气丹' }` | **本回合自己打出过**这张牌（"两牌配合"） | 待用 |
| `op: 'double_card_effect'` + `names` | 使用指定牌时效果翻倍（牌＋牌联动的另一种写法） | 【陈巧倩】配【补气丹】【回气丹】 |

> 细节见 `docs\规则文档.md` 的「`if` —— 条件」一节；求值实现 `engine.js matchConditions()`（为测试导出），
> 专测 `tests\conditions-test.js`（33 项）。

## 3. 三条铁律

1. **一个时点 = 图上的一格。** 新卡只能从 §2 挑坐标；表里没有的一律不许写
   （编辑器"第 0.5 步"会拦：引擎从不触发的事件直接拒绝保存）。
2. **当前回合玩家优先；对战内改为「阶段主优先」。** 同一个时点上：当前回合玩家**先被询问**、**先表态**；
   其余按座位序。**例外（2026-10-05 用户拍板）**：对战出牌阶段（先攻/后攻投骰前）由**投骰者先表态** ——
   先攻阶段先攻先被问、后攻阶段后攻先被问。
   响应链里**后出手的先结算**（这条规则叫**「后发先至，逆序收势」**，见 §6）。
   > 引擎现状：`responderOrder()` 实现"回合玩家优先、其余按座位"；对战出牌窗口经
   > `ctx.order = [投骰者, 对方]` 显式指定阶段主；链的倒序结算在 `resolvePending()`。
3. **只有一种写法。** 时点类效果一律写 `{event, subject, phase}`；旧 `when` 只作为**兼容层输入**
   留在引擎里，不出现在新数据里（迁移见 §5）。

### 3.1 阶段事务模型（2026-10-05 用户设计，探索阶段为样板）

一个阶段的**基础行动**（探索 = 抽 2 宝物）永远**沉在栈底、最后结算**：

```
进阶段 → 该时点效果先入【斗法】→ 逆序收势 → 有人发动过就再问一轮
       → 连续不发动 → 最后才落基础行动（可被效果替换/修正）
```

- **增量型**（【御风诀】【掌天瓶】）：收势时立即结算（多抽 1 张），基础行动照旧；
- **替换型**（【青易居士】）：收势时只**登记**（`state.phaseMods.exploreSwap`），基础行动读登记改抽；
- **「可以」= 主动发动**：卡文带「可以/可选择」的效果**必须问玩家**，数据上就是
  `event + 无 auto`（进询问候选）；不带「可以」的自动触发照旧 `auto: true`（不进询问）；
- **防循环**：可再问一轮的前提是 `oncePerTurn: true` 把已发动的滤掉，问无可问自然停；
- 实现：`doDrawTreasure` 的 `signal.chainLength`（`resolvePending` 回传"这一轮有没有人发动"）+
  resume 递归重进；专测 `tests\explore-phase-test.js`。

#### 3.1.2 受伤窗口**前置**（本轮的核心）

用户 2026-10-05：「**受伤也是时点，时点响应，那么原效果最后生效**」。
`applyDamage` 现在就是受伤时点的阶段事务：

```
伤害进来 → 开【斗法】窗口（伤害还没落地，连减免都还没算）
        → 逆序收势：响应直接改"待落地的伤害" ctx.pending.value
        → resume 回来落**基础行动**：减免（护体灵光/替挡）→ 扣血
          → "受伤时"的自动效果（【燕如嫣】【慕沛灵】）→ 濒死判定
```

- 四个响应改的都是**同一笔待落地的伤害**：`damage_cancel`（→ 0）、`damage_multiply`（× N）、
  `puppet_absorb`（→ 0，傀儡替伤）、`damage_save_dice`（【遮天钟】掷骰抵消／6 点反弹等额）；
- `ctx.lostHp` / `$lostHp` 跟着 pending 走 —— 后结算的响应看到的是"前面已经改过"的数值；
- `if: {lethal: true}` 用的 `ctx.lethal` 是**粗判**（`生命值 − 待落地伤害 ≤ 0`）；
  `damage_multiply` 把伤害翻到致命时会把 `ctx.lethal` 置真 → 后面才结算的【还阳术】照样被问得出来；
- **零响应直通**：没人能响应（例如手里只有 `auto` 类的【燕如嫣】）时 `fireTiming` 返回 `opened:false`，
  伤害立刻落地 —— 与旧行为一致，不会平白多一次弹窗；
- **旧的事后补救通道删掉**：`ctx.deferredDeath`（"伤害先落地、判死延后"）整条退役；
  【傀儡蜥蜴】现在是"替主人把这一下**挡掉**"（血量根本不掉），不再是"先扣血再补回来"；
- 文案跟着改：窗口期间是"**即将**受到 N 点伤害"、"这次伤害将使生命值归零——不出手就出局"，
  收势之后才有战报那条"受到 N 点伤害"；
- 专测：`tests\response-uses-dice-test.js` [C]（窗口前置 + `ctx.pending` + 三分支）、
  `tests\interrupt-test.js` [D]/[E]（遮天钟、还阳术救人与不救）、`tests\p0-regression-test.js` [E3]（傀儡替伤）。

### 3.2 对战出牌阶段 = 优先权循环（2026-10-05 用户拍板）

先攻/后攻出牌阶段（投骰前）不再是"开一次窗就投骰"，而是**阶段主优先的循环**：

```
阶段主（投骰者）先表态 → 对方响应 → 循环 → 双方连续不发动 → 逆序收势
→ 链非空再问一轮（回到阶段主继续发动）→ 一轮谁都没发动 → 推进到投骰
```

- **阶段主优先**：`doRoll` 给 `roll·before` 窗口传 `ctx.order = [投骰者, 对方]`（铁律 2 在对战内的应用）；
- **重开**：复用 `signal.chainLength`（§3.1 同款）；链为空才推进投骰；
- **防重复问**：出牌阶段里发动过的**场上**牌登记到 `combat.firedRollBoard`，重开的窗口不再问
  （手牌打出去就没了不需要这道；【乾蓝冰焰】效果2 这种没有 oncePerTurn 的场上牌靠它不被反复扣费）；
- **零响应直通**照旧：双方都无牌可发动时根本不弹窗；
- 专测 `tests\combat-priority-test.js`；前端战斗面板显示「当前时点 + 谁在表态」。
