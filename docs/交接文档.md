### 4.0j 第十五轮（2026-10-06）：⭐ **同一个浏览器开两个窗口 = 两个玩家**（用户报「双方都显示我方胜利」）

用户原话：**「战斗结算胜利时，双方都显示我方胜利，应该是显示bug」**；追问后确认：
道号不一样、是**同一台电脑上开了两个窗口**。

- **先排除结算代码**：真浏览器两个独立会话打到分出胜负、逐帧采样两边 DOM —— 顶部状态条、
  斗法弹窗战况条（「你 领先 3 : 2 —— 你正获胜！」／「南宫婉 领先 3 : 2 —— 南宫婉 获胜」）、
  面板金边高亮、闪烁横幅、战报**逐处都按"看屏幕的人"分视角**，没有一处写死"我方" ⇒ 不是结算的锅。
- **真根因**：会话只存 `localStorage`，而 **localStorage 全浏览器只有一份** —— 窗口2 一加入就把
  窗口1 的座位覆盖掉；窗口1 一刷新/重连就读到窗口2 的座位 ⇒ **两个窗口其实是同一个玩家**，

## 7. 踩坑清单（新会话最容易重犯的）

1. **PowerShell 写中文/引号极容易出错** —— 内联 `node -e "..."` 带中文或嵌套引号会被 mangle。
   **一律写成临时 .js 文件再 `node <file>`**（这轮又栽了两次）。
2. **这个仓库数行数别用 `Get-Content .Count`**（会少算 400+ 行），用 `node` 或 read 工具。
3. **`Select-String -SimpleMatch` 里写 `\(` 会当字面反斜杠**，统计函数调用次数会得到 0。
4. **改 `server\` 或 `data\cards.json` 后必须重启**才能生效；`public\` 不用。
   反之：**改了 `public\` 却不重启 `server\`，线上就是"新前端 + 老引擎"错配**。
5. **UI 测不能并发跑**（CDP 端口会撞）；跑全量时别同时跑别的 UI 测试。
6. **加了"引擎挂起等人操作"的状态，必须扫一遍所有随机驱动 harness** ——
   `state.pending` 是这样，`state.forceDiscard` 也是这样（改完 `smoke.js` 立刻死锁过一次）。
7. **测试台/工具的"通过数虚高"与"靠运气的断言"同样有害** —— 这轮抓到 13 处 `check(名, true)`，
   以及一个"弃 5 张会溢出、弃 4 张不会"的滚动条断言（本地过、线上挂）。**断言要确定性**。
   第二轮又栽一次同类：`p0` [E2] 写死"骰点附加 = 2"，只在 `raw=5` 时成立 —— 灵根配比一改随机流漂移就假红。
   **判据**：断言必须"能判别"（改坏了会红）；只会"恰好为真"的断言等于没测。
8. **别信交接文档里的数字** —— 上一份说 engine.js 3563 行、23 个套件，实测 3633 行 / 39 个套件。
   结论方向往往对，**数字和行号只能当线索**。
9. **`data\cards.json` 有大改动前先备份**（`cards.json.bak-<原因>`），这轮留了 `.bak-pre-xutianding`。
10. **改了消耗随机数的规则，会连带影响所有"写死骰点"的旧断言** —— 本轮把灵根配比一改，
    4 人局开始走"同资质掷骰争先手"（多消耗 2 次随机数），下游所有掷骰结果整体漂移。
    `smoke.js` / `balance-stats.js` 这类随机驱动 harness 没事，**写死具体点数的断言会假红**。
11. **找进程 PID 别按命令行模糊匹配** —— `Get-CimInstance Win32_Process | Where CommandLine -like '*server\index.js*'`
    会把 **DSH 自己的 PowerShell 运行器**也匹配上（它的命令行里嵌着整段脚本原文，其中就有 `server\index.js` 字样），
    脚本会**把自己 kill 掉、后面的 `Start-ScheduledTask` 不执行** —— 本轮就这么让线上空了 2 分钟。
    **按监听端口找**：`(Get-NetTCPConnection -State Listen -LocalPort 8094).OwningProcess`。
12. **这台机器上的 PowerShell 是 5.1**（不是 pwsh 7）：没有 `-Encoding utf8NoBOM`、没有
    `[System.IO.File]::AppendAllBytes`。给 `<内部运维文档>`（UTF-8 **无 BOM**）追加日志要用
    `[System.IO.File]::Open(..., Append)` + `ReadAllBytes` 按字节写，别用会加 BOM 的方式。
13. ⭐ **`data\cards.json` 有两条写入路径，旧页面存盘会整段覆盖（2026-10-05 真事故）**：
    会话用 `edit`/脚本**直接改文件**是一条路，用户在 **8098 页面**里改是另一条路 ——
    页面持的是**载入那一刻的快照**，`/api/save` 写的是"浏览器发来的整份卡池"，
    **谁后存盘谁赢，先存的那边无声消失**。那次事故：`02:13` 的旧页面存盘把 `01:43` 刚修的
    【掌天瓶】/【降尘丹】两处卡数据整段回退，3 个套件变红，被误判成"引擎真回归"，白查一轮。
    **判据**：看到"刚改的数据没生效 / 若干测试突然红"，**先 `git diff -- data/cards.json` 和
    `Get-ChildItem data\cards.json*` 看是谁写的**，别急着怀疑引擎。
    根治：`/api/save` 现在认 `baseMtime`（对不上 → 409，前端 confirm 后才 `force` 覆盖）；
    **但用户在 8098 页面里仍要按 F5 刷新**，否则他会对着旧快照编辑。
14. ⭐ **"两边显示不一样"的报障，先确认两个窗口是不是同一个玩家（2026-10-06 用户报「双方都显示我方胜利」）**：
    用户是**同一台电脑开两个窗口**玩，而会话原来只存 `localStorage`（**全浏览器一份**）——
    窗口2 一加入就把窗口1 的座位覆盖掉，窗口1 一刷新就变成窗口2 的玩家，于是两个窗口是同一个人，
    谁赢都显示「你赢了」。
    **判据**：先看两边**牌桌右上角那个道号 chip（`#tb-me`）是不是同一个名字**，再看
    `sessionStorage` / `localStorage` 里的 `fanren.jieying.session.v1`。
    现已修成**按窗口存**（`sessionStorage` 为主 + 座位心跳，见 §4.0j），回归 `tests\ui-two-windows.js`。
    ⚠️ 反面教训：**别一上来就怀疑渲染层** —— 这轮把结算路径（状态条/战况条/金边/横幅/战报）
    逐帧采样了一遍，全是按视角分的、没有一处写死"我方"，白查了一大圈。
