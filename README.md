# 凡人修仙传 · 结婴之战（网页版）

把实体桌游《凡人修仙传：结婴之战》复刻成的**可联机网页版桌游**：2～4 人、房间制、**零 npm 依赖**、
纯 Node 内置模块 + 原生前端，一条命令起服务，手机/平板扫码就能一起玩。

> 规则来自官方规则讲解视频的逐句转写 + 实物卡面逐字校对，不是臆造；所有"卡文没写清"的地方都在
> [`docs/规则文档.md`](docs/规则文档.md) 里以 `【裁定】` 标记逐条记录（房规唯一真相源）。

---

## 快速开始

需要 **Node.js ≥ 18**（开发用 v24），**没有任何 npm 依赖**。

```bash
git clone <本仓库地址> fanren-jieying
cd fanren-jieying
node server/index.js            # 默认监听 0.0.0.0:8094
```

浏览器打开 `http://127.0.0.1:8094` → 输入道号 → **创建房间** → 把 4 位房间码给其他人 →
他们输房间码**加入** → 房主点「开仙门」。

- **同一台电脑开两个窗口当两个玩家**：可以。座位**按窗口**记（`sessionStorage`），刷新各回各的座位。
- **手机/平板**：和主机同一个 WiFi，访问 `http://<主机局域网 IP>:8094` 即可（放行防火墙端口见下）。
- **公网联机**：见 [`docs/部署教程.md`](docs/部署教程.md)（Caddy / Nginx 反代 + HTTPS + 常驻服务）。

想改端口：`PORT=8095 node server/index.js`（Windows PowerShell：`$env:PORT=8095; node server/index.js`）。

## 目录结构

```
.
├─ server/                服务端（零依赖）
│  ├─ index.js            房间制 HTTP + SSE 服务端
│  ├─ engine.js           规则引擎：纯状态机（createGame / act / publicState，不碰 IO）
│  ├─ cards.js            卡池加载与牌堆构建
│  └─ effect-meta.js      时点/效果元数据（阶段图、op 表、时点标签的唯一权威）
├─ public/                前端（原生 HTML/CSS/JS，无框架无 CDN，完全离线可用）
├─ data/cards.json        卡池数据（209 张 / 122 种；可用编辑器改）
├─ tools/
│  ├─ editor/             卡片编辑器 + 效果沙盒（8098，自带 HTTP / 浏览器自测）
│  ├─ verify-dsl.js       卡池 DSL 硬校验（40 项）
│  ├─ lint-cards.js       卡池体检（硬错误 / 未实装 / 描述与实现对不上）
│  └─ gen-cardlist.js     生成 docs/卡牌一览.md
├─ tests/                 回归测试（引擎 36 套 + 真浏览器 UI 15 套）
│  ├─ run-all.js          一把跑完全部：node tests/run-all.js [--no-ui]
│  └─ cdp.js              零依赖 CDP 客户端（驱动本机 Edge 跑真浏览器测试）
├─ docs/                  规则文档 / 时点规范 / 卡牌一览 / 部署教程 / 开发交接
└─ run-fanren.cmd         Windows 常驻启动脚本（纯 ASCII + 自愈循环，配合计划任务）
```

## 测试与自检

```bash
node tests/run-all.js --no-ui        # 引擎 + 服务端（36 套，约 1 分钟，不需要浏览器）
node server/index.js &               # UI 套件需要一个在跑的服务
BASE=http://127.0.0.1:8094 node tests/run-all.js   # 全量 51 套（含 15 套真浏览器 UI）
node tools/verify-dsl.js             # 卡池 DSL 不变量
node tools/lint-cards.js             # 卡池体检
```

- `tests/smoke.js`：2/3/4 人随机对局，校验不变量并全部终局。
- `tests/balance-stats.js 24`：跑若干局统计胜因占比 / 回合数 / 平手率。
- UI 套件用**真浏览器**（本机 Edge + CDP）跑两个到四个独立 profile，因此必须串行执行。
- 服务端自带 `GET /healthz` 与 `GET /api/version`（含 pid / 启动时间 / 引擎与卡池哈希 / `stale`），
  一条命令验证"端口上跑的到底是不是最新代码"：`node tools/deploy-check.js`。

## 核心机制速览

| 机制 | 规则 |
|---|---|
| 目标 | 首个晋升**元婴**者胜；或最后一位存活者胜 |
| 境界 | 凡人→炼气→筑基→结丹→元婴，基础战力 1~5 |
| 生命 / 法力 | 生命上限 **6**；法力上限 **12**（凡人期只有 6），每回合恢复 1 点 |
| 晋升 | 灵根牌**门槛** + 面板**消耗**（0/2/2/3）+ 掷骰（结丹 ≥4、元婴 ≥5） |
| 灵气牌 | 4 种共 60 张；抽完自动续一整组；灵气值 = 灵气区张数 |
| 对战 | 每回合 1 场；不可打低于自己两个境界者；被指定不可拒绝 |
| 骰点 | **查表**：1→+0，2~5→+1，6→+2；最终战力 = 基础 + 骰点附加 + 装备/同行者 + 卡牌修正 |
| 装备收费 | 卡文带「装备时不消耗【法力值】」→ 装备免费、**发动其效果时才消耗**（费用印在效果上）；没写 → 装备时付角标、效果不再消耗 |
| 斗法 | 出牌/响应走**斗法链**：后发先至、逆序收势；「对方出牌时」= 链上那一环结算之前 |
| 时点询问 | 只摆给**真有牌可响应**的人；需要付费的**到点必问**（付不起静默跳过） |
| 同行者 | 无境界限制、只占位；部分占 2 格；分「承伤型」与「替挡型」 |
| 手牌上限 | 宝物 6 张，法术 / 同行者各 2 张 |
| 淘汰 | 使对方生命归零者，可从对方剩余卡牌中任选 3 张 |

完整规则见 [`docs/规则文档.md`](docs/规则文档.md)；时点表与"窗口何时弹"见
[`docs/时点规范.md`](docs/时点规范.md) 与 [`docs/锁链规则细则.md`](docs/锁链规则细则.md)。

## 卡片编辑器

`tools/editor/` 是一个自带服务端的卡片编辑器（8098）：全字段编辑、五步保存闸门（结构 → 参数类型 →
时点接线 → DSL 校验 → 数量）、批量改张数、新建/删除卡、与磁盘版的差异视图、效果沙盒与平衡试跑。

```bash
node tools/editor/server.js                  # → http://127.0.0.1:8098
node tools/editor/selftest.js                # HTTP 端到端自测（跑在临时副本上）
node tools/editor/selftest-browser.js        # 真浏览器自测
```

## 技术选型

- **零 npm 依赖**：服务端只用 Node 内置 `http` / `crypto` / `fs`；前端无框架、无 CDN。
- **SSE 而不是 WebSocket**：回合制不需要双向实时帧，SSE 自带断线重连、反代零配置、`curl` 可调试。
- **引擎是纯函数状态机**：`createGame / act / publicState` 不碰 IO —— 所以随机对局能跑几千步做自动回归，
  也能在编辑器里拿一份卡池直接试跑平衡。
- **数据驱动**：卡池是 JSON（`data/cards.json`），效果是 `{op, event, phase, subject, ...}` 这样的
  DSL 条目，引擎只认 op；新增一张卡通常不用改引擎。
- **测试当闸门**：改引擎/卡池后先跑 `tests/run-all.js`，红了先查卡池漂移，再怀疑引擎。
